# Backend and client engineering review

## Scope

The Java backend contains 318 source files and about 37,800 lines; it targets Java 27 and Spring Boot 4.1.2. The review also checked the Python 3.14 ML service, browser JavaScript/CSS, and strict TypeScript mobile client. It combines source inventory and dependency scans with local runtime checks. It is not a proof that every endpoint, deployment profile, external integration, or UI state is correct.

## Changes made

| Area | Finding | Change |
|---|---|---|
| Statement workbook | `FinancialStatementExcelGenerator` mixed workbook coordination, financial calculations, styles, and multiple sheets in one roughly 1,800-line class. | Split analysis, workbook snapshot, styles, ledger sheets, and dashboard sheet into focused collaborators. The generator is now a 116-line coordinator. Expense aggregation also computes related totals in one pass. |
| Export responsibilities | `ExportServiceImpl` mixed expense, income, and full-statement persistence and renderers. | Production exports now use expense, income, and full-statement services with narrow dependencies. `ExportServiceImpl` is a deprecated compatibility facade and is no longer a Spring service bean. Controllers depend on their domain export interfaces. |
| Workbook injection and failure | The range Excel renderer interpreted every string starting with `=` as a formula. A live description containing `=SUM(1,1) runtime export probe` caused HTTP 500 and could have become a spreadsheet formula. | String cells are always written as text. Only two internal totals use a separate formula-writing method. Live export verification confirmed the user string remains text and internal SUM formulas still exist. |
| Workbook performance | Expense and income workbooks auto-sized every populated column after writing the rows; the statement ledger did the same. | Replaced those scans with fixed widths. The scan cost grew with the number of rows and repeated column count; fixed width avoids that second pass. |
| Avatar uploads | The request MIME type was trusted and unsupported image data could be stored and served with attacker-supplied image MIME. Decoding had no pixel cap. | Decode only supported raster formats, enforce encoded-byte and image-dimension/pixel limits, normalize to JPEG/PNG, derive the response type from the stored extension, prefer atomic replacement, and send `X-Content-Type-Options: nosniff`. |
| Development secrets | A predictable JWT secret and feedback token were present in default/development properties. The H2 web console allowed remote access. | JWT has no repository default; development generates a process-local 256-bit key when `JWT_SECRET` is absent. Development feedback token is empty unless supplied, governance fails closed, and the H2 console rejects remote clients. Production still requires an explicit `JWT_SECRET`. |
| Browser rendering | Legacy auth pages inserted user-entered email and server messages with `innerHTML`; dashboard avatar HTML interpolated names and URLs into markup and inline handlers. | Message output uses `textContent`; dashboard avatars now use DOM nodes and an error listener, and reject unsafe URL schemes. Budget period/date attributes are escaped. Currency fallback formatting uses `Intl.NumberFormat`. |
| Legacy page structure/accessibility | `legacy-mobile.html` contained over 3,000 lines of inline CSS and script, disabled zoom, and prevented text scaling. | Moved CSS and JavaScript to `css/legacy-mobile.css` and `js/legacy-mobile.js`; markup now links those assets. Restored zoom/text scaling and added `viewport-fit` and a `dvh` height fallback. |
| Mobile credential storage | When SecureStore returned no value or failed, token reads could consult plaintext AsyncStorage fallback entries. | Token/biometric keys no longer read from plaintext fallback. Custom API URLs reject credentials/query fragments and require HTTPS except loopback HTTP. |
| ML model provenance | The resolver could fall back to Hugging Face `main` while metadata claimed the configured revision. Health and metadata calls also loaded four auxiliary joblib artifacts, including 452 MB and 138 MB files, just to report status. | Report the selected revision label (`main`, `local`, or the configured revision). Health and metadata now report lazy auxiliary models without loading them; inference endpoints still load an auxiliary model on first use. |
| Database failover and retraining | Earlier review found unsafe fallback overwrite paths and retraining process lifecycle/working-directory issues. | Existing changes retain the fallback write guard/lease drain, streamed Hugging Face database transfer, bounded retraining logs, timeout/termination, and `ml/` process configuration described in the previous review. Remote recovery and real retraining still require credentials and are not verified here. |

## SOLID and coupling status

Production wiring now routes expense and income exports through domain-specific services. Full statements remain a cross-domain use case, so their service owns the query orchestration and passes data to renderers. The report package still has large classes such as `ExecutiveExcelReportGenerator`, `MonthlyHtmlReportGenerator`, and `FallbackSyncEngine`; package dependency cycles also remain. A source scan of `*Controller.java` found no repository imports or repository-typed fields/parameters. Repository access in application services remains expected; the full-statement query service is one intentionally cross-domain boundary.

The backend is not yet uniformly SOLID. Remaining design debt includes package cycles, older optional collaborators and compatibility constructors, large report renderers, and user/account lifecycle orchestration across domains. The mobile app has many reusable components and injected services, but the adoption audit found 66 uses of `any`; the browser client remains classic scripts with global integration points. This pass makes targeted boundary improvements rather than claiming a complete architectural rewrite.

Browser JWTs now use an HttpOnly, SameSite cookie with a CSRF token bound to the session JWT. The browser migrates valid legacy `localStorage`/`sessionStorage` JWTs through `/api/auth/session`, then removes them; if the API is unreachable the old token remains temporarily to preserve the session and retry. Mobile bearer-token responses remain unchanged. Credentialed CORS is restricted to explicit origins. Dynamic HTML sinks still need ongoing source-level review.

## Runtime verification

- Spring Boot started on Java 27 / Boot 4.1.2 against an isolated in-memory H2 database with `SERVER_SSL_ENABLED=false`, ML autostart disabled, and `JWT_SECRET` unset. The dev profile logged that it generated an ephemeral JWT key. Registration/login and an authenticated statement export succeeded. The default SSL setting is false because TLS terminates at the hosting proxy; enabling `SERVER_SSL_ENABLED=true` still requires valid TLS material.
- Live authenticated requests returned HTTP 200 for all 12 export routes: expense and income CSV/JSON/XLSX/PDF, complete statement XLSX/PDF, and range XLSX/PDF. The workbooks opened as ZIP containers with workbook/sheet XML, and PDFs had valid PDF headers/trailers. The range workbook preserved a description starting with `=` as text. Expense XLSX took 2.265 seconds in the second smoke run; this is not a controlled before/after benchmark.
- A live SVG-with-script avatar upload returned HTTP 400. A valid PNG upload returned HTTP 200, and the retrieved avatar had `image/png` plus `X-Content-Type-Options: nosniff`.
- The anonymous ML feedback route returned HTTP 403 while no feedback token was configured.
- The Python ML service loaded the local TF-IDF artifact, returned health HTTP 200, classified `SWIGGY food delivery` with HTTP 200 in 68 ms, and returned subsequent health in 2 ms. All four auxiliary models remained lazy. The first health call took 3.355 seconds including model load.
- The legacy page, extracted CSS/JS, index page, and dashboard page all served HTTP 200 from a local static server. Node syntax checks, mobile TypeScript check, Python compile/ruff, and Java `test-compile` passed. No test suites were executed.
- Browser-session runtime checks against isolated H2 confirmed browser login returns no JWT body and sets an HttpOnly `ET_SESSION` cookie plus a readable `ET_CSRF` cookie; authenticated profile and expense reads worked through the cookie. An unsafe request without CSRF returned 403, valid-CSRF logout returned 204, legacy bearer exchange removed the browser JWT, and a separate mobile-style bearer login continued to access protected APIs.
- Playwright exercised the normal sign-in page, dashboard, legacy sign-in and legacy ledger at desktop and mobile sizes. Normal and legacy sign-in succeeded with no browser page errors; JWTs were absent from localStorage, and the reviewed viewports reported no horizontal overflow. Screenshots and viewport metrics were written outside the repository under `/tmp/expense-tracker-ui-review`.

## Verification limits and modernization opportunities

Hugging Face database restore/backup and scheduled ML retraining were not exercised because `HF_TOKEN` and `DB_BACKUP_KEY` are not available. Production TLS/proxy behavior, remote model loading, and cross-device mobile runtime remain unverified. Joblib artifacts are executable pickle content and must remain restricted to trusted, controlled model repositories and build artifacts.

The adoption audit still reports 28 hand-built modal overlays, 1,767 `!important` declarations, and no CSS layers. These are broad modernization opportunities; replacing every overlay or stylesheet rule automatically would risk changing behavior. Continue gradual dialog migration with visual/browser validation. Avoid blanket CSS rewrites. For Java, avoid converting remaining large renderers in one pass; extract one responsibility at a time with live file-format checks.

`./mvnw -q -DskipTests test-compile` passes. The existing Lombok annotation processor emits a JDK warning about `sun.misc.Unsafe.objectFieldOffset` being marked for removal.
